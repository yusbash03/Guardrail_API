# Database Schema (PostgreSQL 16+, Neon)

Conventions: `snake_case`; UUID v7 PKs generated by the app; `timestamptz` UTC; money `numeric(14,2)` + `currency char(3)`; enum columns are `text` with `CHECK`; optimistic concurrency on mutable aggregates via PostgreSQL `xmin` (Npgsql `IsRowVersion()`).

Tables required by the brief are all present. **Additions** (needed for correctness): `refresh_tokens`, `categories`, `idempotency_keys`.

> DDL below is the target shape; EF Core migrations generate the real DDL. CHECK lists must match DOMAIN_MODEL.md.

## Identity

```sql
create extension if not exists citext;

create table users (
  id               uuid primary key,
  email            citext not null unique,
  password_hash    text not null,
  display_name     text not null check (length(display_name) between 1 and 80),
  role             text not null default 'USER' check (role in ('USER','ADMIN')),
  is_active        boolean not null default true,
  last_login_at    timestamptz,
  created_at       timestamptz not null,
  updated_at       timestamptz not null
);

create table refresh_tokens (
  id               uuid primary key,
  user_id          uuid not null references users(id) on delete cascade,
  family_id        uuid not null,
  token_hash       char(64) not null unique,       -- SHA-256 of the opaque token
  expires_at       timestamptz not null,
  revoked_at       timestamptz,
  replaced_by_id   uuid references refresh_tokens(id),
  created_ip       inet,
  created_at       timestamptz not null
);
create index ix_refresh_tokens_user on refresh_tokens(user_id);
```

## Spending profile and policies

```sql
create table categories (
  code             text primary key,               -- GROCERIES, HOUSEHOLD, ...
  name             text not null,
  description      text,
  sort_order       int not null default 0
);

create table spending_profiles (
  id                         uuid primary key,
  user_id                    uuid not null unique references users(id) on delete cascade,
  currency                   char(3) not null default 'USD',
  time_zone                  text not null,          -- IANA, e.g. 'Africa/Lagos'
  current_policy_version_id  uuid,                   -- FK added after policy_versions
  created_at                 timestamptz not null,
  updated_at                 timestamptz not null
);

create table policy_versions (
  id                    uuid primary key,
  spending_profile_id   uuid not null references spending_profiles(id) on delete cascade,
  user_id               uuid not null references users(id),
  version_number        int  not null check (version_number >= 1),
  snapshot_json         jsonb not null,             -- canonical PolicySnapshot
  snapshot_hash         char(64) not null,
  change_summary        text not null,
  created_by_actor      text not null check (created_by_actor in ('USER','SYSTEM')),
  created_at            timestamptz not null,
  unique (spending_profile_id, version_number)
);
alter table spending_profiles
  add constraint fk_profile_current_version
  foreign key (current_policy_version_id) references policy_versions(id) deferrable initially deferred;

create table spending_policies (
  id                 uuid primary key,
  policy_version_id  uuid not null references policy_versions(id) on delete cascade,
  user_id            uuid not null references users(id),
  rule_type          text not null check (rule_type in (
      'CATEGORY_BUDGET','SPENDING_LIMIT','MAX_TRANSACTION_AMOUNT','APPROVAL_THRESHOLD',
      'MERCHANT_ALLOW','MERCHANT_BLOCK','NEW_MERCHANT_POLICY','PRODUCT_RESTRICTION',
      'DUPLICATE_PURCHASE','TIME_RESTRICTION','UNBUDGETED_CATEGORY_POLICY')),
  category_code      text references categories(code),
  merchant_id        uuid references merchants(id),
  product_id         uuid references products(id),
  parameters         jsonb not null default '{}',   -- schema per rule_type, see SPENDING_POLICY_ENGINE.md
  is_enabled         boolean not null default true,
  created_at         timestamptz not null
);
create index ix_spending_policies_version on spending_policies(policy_version_id);
-- Rows are immutable once their version exists (enforced in code; optional trigger).
```

## Data isolation

- Every user-owned table has `user_id`. Repository base applies `WHERE user_id = @currentUser`.
- Integration tests create two users and assert cross-access returns 404 for every `GET /{id}` endpoint.
- Optional hardening (P2): PostgreSQL Row-Level Security with `set_config('app.user_id', …)` per connection. Not required for MVP because Neon pooled connections + EF make RLS session settings error-prone.

## Append-only tables

`policy_versions`, `spending_policies`, `policy_evaluations`, `spending_ledger_entries`, `audit_logs`, `agent_executions`. The application never issues UPDATE/DELETE on them. P1 hardening: a DB trigger raising on UPDATE/DELETE.
